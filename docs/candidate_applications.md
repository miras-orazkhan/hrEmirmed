# Рассмотрения кандидатов

API `/api/v1/candidate_applications` поддерживает список (GET), получение по ID (GET) и создание (POST). Список фильтруется по `candidate_id`, `job_requisition_id`, `status`; пагинация — `cursor` и `limit`, продолжение в `X-Next-Cursor`.

Создание: `{"candidate_application":{"candidate_id":1,"job_requisition_id":2}}`. Операция доступна назначенному на заявку рекрутеру с разрешениями `read.candidate` и `manage.candidate_application` или администратору. Заявка должна быть в подборе, кампания — активна, потребность — не заполнена. Рассмотрение закрепляет текущую версию условий заявки; последующие изменения заявки её не подменяют. Начало рассмотрения также назначает ответственным за карточку кандидата рекрутера заявки в той же транзакции. Начало рассмотрения в текущем модуле является явной командой сотрудника; автоматическое начало диалога относится к будущей интеграции.

У кандидата может быть только одно активное рассмотрение во всей системе. Ограничение защищено частичным уникальным индексом PostgreSQL и блокировкой карточки кандидата. После завершения предыдущего рассмотрения новое разрешается только при `allow_next_application: true`.

POST `/:id/advance` продвигает на следующий этап, определённый сервером:

| Исходный этап | Следующий этап | Кто принимает решение |
| --- | --- | --- |
| screening | test_review | Назначенный рекрутер |
| test_review | interview | Назначенный рекрутер |
| interview | internship, если стажировка обязательна; иначе offer | Интервьюер закреплённой версии условий |
| internship | offer | Руководитель стажировки закреплённой версии условий |

Ручной переход к проверке теста — временная граница текущего модуля: он не создаёт тест, ответы или оценку. До реализации тестов, календаря и оценок прохождение этих этапов фиксируется сотрудником вручную. На этапе `offer` продвижение останавливается до реализации оформления. Этот API не уменьшает количество свободных мест и не позволяет выставить `hired`.

POST `/:id/finish`: `{"candidate_application":{"outcome":"rejected","rejection_reason_id":1,"decision_comment":"Комментарий","allow_next_application":false}}`.

Допустимы `rejected` и `withdrawn`. При отказе требуется действующая причина из справочника. Решение о следующем предложении должно быть явным JSON boolean, включая `false`; строки и отсутствие значения отклоняются. На собеседовании решение принимает назначенный интервьюер, на стажировке — её руководитель, на остальных этапах — рекрутер заявки. Этап принятия решения сохраняется, `status` становится `completed`, фиксируются автор и время. Повторное завершение отклоняется.

Пауза заявки блокирует начало, продвижение и завершение рассмотрений. Политика паузы является рабочим допущением до уточнения открытых вопросов ТЗ. Решения не отправляют внешних сообщений. Доступ руководителей ограничивается рассмотрениями, переданными им на соответствующий этап; другие рассмотрения того же кандидата не раскрываются. Доступ к завершённым рассмотрениям сохраняется у назначенных сотрудников на тех же условиях до согласования окончательной политики архивного доступа.

Все изменения выполняются в транзакции с порядком блокировок: кампания → заявка → кандидат → рассмотрение. Журнал аудита фиксирует состояние процесса без текста комментария и контактных данных.
