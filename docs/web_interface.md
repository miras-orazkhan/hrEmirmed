# Рабочий интерфейс

## Direction contract

Режим Operate. Первичная аудитория — рекрутер, работающий с очередью кандидатов и заявками. Основание дизайнера: расписание приёма клиники (seed 69c7d062, grounded direction 5). Ритм строк, фиксированные колонки, статус и ответственное лицо помогают быстро находить запись. Детальная карточка отделяет персональные данные от доступных пользователю рассмотрений. Дневное офисное использование — предположение; светлая поверхность снижает резкий контраст с бумажными документами.

Первый экран: навигация по разрешённым разделам, заголовок реестра, поиск и действие создания, затем содержательные строки либо честное пустое состояние. Нет выдуманных показателей. На мобильном навигация сверху, строки превращаются в вертикальные записи. Поиск заменяет только Turbo Frame `workflow_list`; поле поиска остаётся вне заменяемого блока. Рассмотрения на карточке кандидата живут в отдельном Turbo Frame `applications_candidate_<id>`. Начало рассмотрения отправляется в `_top`, поскольку доступные заявки могут принадлежать другим рекрутерам и после создания нужно обновить заголовок владельца карточки. Перевод этапа и завершение обновляют сам блок рассмотрений. Формы используют Turbo Drive, успешные записи перенаправляют с HTTP 303, ошибки валидации возвращают HTTP 422. Разработка началась сразу в коде по прямому запросу пользователя; постоянный buildPath не задаётся.

Дисциплины challengers из задания дизайнера: specimen — различимость типов текста; Labanotation — читаемые состояния без обязательного знания символов; metro — устойчивое расположение разделов; gate board — выравнивание строк; Crouwel — модульные отступы; centre rail — ограничение ширины форм. Они не заменяют операционную очередь и не вносят декоративные мотивы.

## Область реализации

Реализовано в HTML:

- Вход и выход (encrypted HttpOnly SameSite cookie, CSRF, `Cache-Control: no-store`)
- Кандидаты: реестр, карточка, создание/изменение, защищённые резюме
- Шаблоны вакансий, заявки на подбор, кампании (запуск/пауза/возобновление/отмена)
- Рассмотрения: старт, перевод этапа, завершение с явным решением о следующем подборе
- Администрирование: сотрудники, роли, филиалы, подразделения, юрлица
- Справочник причин отказа (чтение при `read.candidate`, изменение при `manage.rejection_reason`)

Пока только через API (веб-экранов нет): JSON-импорт кандидатов и разрешение возможных дублей. Переходы стадий ручные; интерфейс не имитирует отправку тестов или сообщений. Оформление найма, каналы и ИИ не реализованы.

HTML использует существующие бизнес-сервисы. Active Storage public routes выключены. JavaScript и CSS локальные, CDN не нужен. Реестры используют keyset pagination по 50 записей. На карточках последние 50 рассмотрений; полная постраничная история резюме доступна отдельно.

## Реализация и проверка

Веб-поверхность: серверные Rails views, Turbo Drive/Frames, Stimulus-контроллер задержанного поиска. Стили в `app/assets/stylesheets/application.css`; breakpoint — 800px. Визуальные токены извлечены в [DESIGN.md](../DESIGN.md).

Интеграционные проверки: `test/integration/web_interface_test.rb`, `web_settings_test.rb`, `web_security_test.rb`.

### Известные дефекты (на 17.10.2026, требуют правки кода)

1. **Частичный PATCH сотрудника.** `Web::UsersController#user_attributes` подставляет пустой `department_ids`, если ключ не передан. Из-за этого обновление только `full_name`/`active` обнуляет подразделения и возвращает 422. Нужно: включать `department_ids` только при наличии ключа в запросе; в форме — скрытое поле `user[department_ids][]`, чтобы снятие всех галочек очищало набор явно.
2. **Тест пагинации справочников.** `WebSettingsTest` создаёт 45 юрлиц при `PAGE_SIZE = 50`, поэтому next-страница не появляется. Нужно создавать не меньше 51 записи (в тесте — 55).
3. **Навигация «Причины отказа».** Пункт меню завязан на `manage.rejection_reason`, тогда как список доступен при `read.candidate`. Для читателя справочника пункт должен показываться по `read.candidate`.

После этих правок перезапустить `bin/rails test`, RuboCop и Brakeman и зафиксировать итоговые числа здесь.
