# Оригиналы резюме

Файл сохраняется без преобразования в приватном Active Storage. Локальные сервисы используют `storage/` и `tmp/storage/`, вне каталога `public/`. В production резервировать нужно и PostgreSQL, и хранилище файлов.

## API

Все операции требуют Bearer-сессию и доступ к кандидату.

- `GET /api/v1/candidates/:candidate_id/resumes` — метаданные, пагинация `limit` / `cursor`, заголовок `X-Next-Cursor`.
- `POST /api/v1/candidates/:candidate_id/resumes` — `multipart/form-data`, поле `file`. Дополнительно нужны права изменения кандидата. Первый приём возвращает 201; повтор одинаковых байтов для того же кандидата — 200 и прежний ID.
- `GET /api/v1/candidates/:candidate_id/resumes/:id` — оригинальные байты с `Content-Disposition: attachment`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`.

Публичные маршруты Active Storage отключены. Метаданные API не содержат ключи хранилища или подписанные ссылки. Доступ проверяется при каждом скачивании.

## Проверки и ограничения

Размер: от 1 байта до 10 MiB. Поддерживаются PDF, DOC, DOCX и UTF-8 TXT. Тип определяется по содержимому через Marcel и сверяется с расширением; переданный клиентом MIME не считается достоверным. TXT дополнительно проверяется на корректность UTF-8 и недопустимые управляющие байты. Имена нормализуются Active Storage. Передача пути к файлу сервера не поддерживается.

Проверка типа не заменяет антивирус: макросы и другие активные элементы документов не удаляются. Сервер не исполняет документы и не строит предпросмотр. Для работы с недоверенными файлами в production следует подключить антивирусную проверку до выдачи файла пользователю.

SHA-256 хранится в `candidate_resumes.sha256`; уникальность `(candidate_id, sha256)` закреплена в PostgreSQL. Блокировка строки кандидата предотвращает параллельное создание двух одинаковых вложений. Запись файла выполняется синхронно; при откате транзакции загруженные байты удаляются. Аварийное завершение процесса между записью файла и фиксацией транзакции может оставить файл без записи в БД: для production требуется периодическая сверка хранилища с таблицей blobs. Размер HTTP-тела также нужно ограничить на reverse proxy: проверка приложения выполняется после приёма multipart-запроса.

Содержимое резюме и имя файла не записываются в аудит. Аудит хранит факт загрузки, пользователя и ID записи резюме.
